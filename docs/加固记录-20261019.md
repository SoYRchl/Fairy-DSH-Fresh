## 1. ★ `fs.watch` 在中文用户名路径下把宿主打挂（最严重）

**症状**：Windows 用户目录含中文时（系统解析成 8.3 短名，如 `C:\Users\<中文名>SO~1\...`），
Node/libuv 直接触发内部断言并打死监听线程：

```
Assertion failed: !_wcsnicmp(filename, dir, dirlen), file src\win\fs-event.c, line 72
```

**不是抛错，是崩** —— 进程还在，但文件事件永远不来。

**命中两处**（同一模式）：

| 文件 | 原实现 | 后果 |
| --- | --- | --- |
| `browser-dock/lib/index.js` + `src/index.js` | `fs.watch(RUNTIME_DIR, …)` 监听 `state.json` | Dock 状态不再推送，界面卡在旧状态 |
| `browser-dock/proxy.cjs` | `fs.watch(runtimeDir, …)` 监听 `command.json` | 关闭/接管命令要等 5 秒对账定时器才生效 |

**修法**：改 `fs.watchFile`（stat 轮询）。`state.json` 用 800ms，命令文件用 300ms。
语义不变（原子 rename 后依然可见），且完全不受短名影响。

**顺带修掉的连带问题**：

- `lib/index.js` 的 `disableWatcher` 里写着 `fallback_poll_ms: 800` 日志，**但其实没有轮询兜底** —— 出错就把监听整个关掉。现在真的有了。
- `proxy.cjs` 的 `spawn` 缺 `error` 监听：`playwright-mcp` 不存在时会变成未捕获异常，宿主只看到进程消失、无任何诊断。现在会记录并置错误态。
- `spawn` 在 `shell: true` 下没给命令加引号：安装路径含空格会被拆断。现在显式加引号。
- 请求体超限时先 `reject` 再 `req.destroy()` ⇒ 400 写进死连接，客户端只见 `ECONNRESET`。现在改为 `req.resume()` 排空 + 正常回 400。

**验证**：`browser-dock` 三个测试从「startup 永久挂死 / state-watch 崩溃」变成 11/11 全绿；在 `C:\Users\<中文名>SO~1\...` 这种 realpath 下也稳定。

## 2. ★ 启动闸门在「DSH 装在别处」时误报，拒绝启动

`fairy-system/preflight-build.js` 里 `yamlAnchor` 的默认值**独立**硬编码成 `~/.local/lib/node_modules/@deepseek-ai/dsh/package.json`，**完全无视** `DSH_OFFICIAL_PACKAGE`。

后果：只要 DSH 不装在那个位置（绝大多数用户），闸门就报

```
scope="profile_lockfile" … actual="MODULE_NOT_FOUND"
```

**修法**：`yamlAnchor` 默认跟随已解析出的 `dshPackagePath`。已验证打包内核里确实带 `yaml`（`<kernel>/node_modules/yaml`），产线路径安全。

测试侧同步修：原来夹具只覆盖 `DSH_OFFICIAL_PACKAGE`，靠本机那份全局安装才解析到 yaml ⇒ **本地全绿、CI 恒红**。现在显式从仓库自己已安装的依赖取 yaml（`fairy-voice` / `balance-meter` 都装了 `yaml@2.9.1`），并加断言：取不到就大声失败，不静默跳过。

## 3. `src/` 与产物失同步：从源码重建必然失败

`fairy-visual/src/index.js` 仍在 `import … from 'dsh-fairy-contracts'`，而该包早已被内联进 `vendor/`（产物 `lib/index.js` 早就改指 `../vendor/fairy-contracts.js`）。

⇒ 任何人想「从 src 重新构建」都会立刻 `ERR_MODULE_NOT_FOUND`。**这属于红线之外的隐性债**：产物是对的，源码是坏的。

**修法**：`src/index.js` 的 import 与产物对齐。

## 4. 安装器死链 + 个人路径泄露

| 问题 | 修法 |
| --- | --- |
| `install.cmd` / `install_full.cmd` 的 `BASE` 写死 `releases/latest/download`，实测 404（本仓库只发 prerelease，GitHub 的 `latest` 只指向非预发布） | 改成 `releases/download/%FAIRY_TAG%`；tag 优先从同目录 `VERSION` 读；`pack.ps1` 打包时把 `__FAIRY_TAG__` 烤成实际版本 |
| `tools/bootstrap.mjs` 打印 `E:/PureEnglishPath/Fairy-DSH-Launch/…` —— 开发机绝对路径进了公开仓库，对别人也是错的 | 改为通用提示 |
| 自己写的注释里带了 `C:\Users\苏阳SO~1` | 打码成 `<中文名>` |
| `shell-hygiene` 已有守卫（禁止 `PureEnglishPath` / 用户名），但**只在被测文件里生效**，工具脚本漏网 | 已逐处清掉；全仓复查只剩守卫自身的白名单 |

> ⚠️ 这两个 `.cmd` 是 **GBK 编码**，只能做**字节级**替换。第一版我用 UTF-8 中文注释插进去，直接产出 11 个 U+FFFD（永久损坏），已 `git checkout` 回滚、改用纯 ASCII 注释重做。
> 同类风险：`edit` 工具会把 `.ps1` 的 UTF-8 BOM 弄丢（`pack.ps1` 已中招），已补回并加了全量核查脚本。

## 5. 测试债：三条断言在「保护 bug」

按 `known-stale.mjs` 自己的原则（**断言当前有意行为，不许放宽/删除**）逐条改：

| 文件 | 原断言 | 为什么是错的 | 现在断言什么 |
| --- | --- | --- | --- |
| `fairy-visual/test/contract.test.js` | `syncDocumentMode(settings.getSnapshot())` | 这正是「全新 home 下 HDD 视觉不亮」的成因；D-053 已改成首同步用归一化值 | 首同步必须归一化；并反向守卫旧写法不得回来 |
| `fairy-visual/test/settings-contract.test.js` | `import … from dsh-fairy-contracts` | 包已内联，整个文件从未真正跑起来 | 引 `vendor/fairy-contracts.js`，测同一份契约 |
| 同上 | `enabled.meta.default === false` | 实现早已是 `true`（首次装上就该看见 HDD 视觉） | 断言 `true` |
| `browser-dock/test/contract.test.js` | 断言 `fs.watch(RUNTIME_DIR)` 与 filename 匹配 | 已改用 `watchFile`（见 §1） | 断言轮询实现 + 反向守卫不得再用裸 `watch` |
| `browser-dock/test/startup.test.js` | —（永久挂死） | `t.after` 在子进程**已退出**时仍 `await once(exit)` ⇒ 永远不返回；夹具只造了 POSIX 壳、Windows 上 `cmd.exe` 找不到文件 | 只在确实活着时才等（带 5s 上限 + SIGKILL 兜底）；按平台补 `.cmd` 夹具 |
