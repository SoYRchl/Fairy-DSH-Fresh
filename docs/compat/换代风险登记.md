## 2. §7 类：已规避的老坑（留作教训）

| 坑 | 现在的做法 |
| --- | --- |
| `text:` / `prefix:` 跟 DSH 版本走 | 预设里**两个键都写**（两边都会忽略自己不认识的那个） |
| `readdir` 的 `Dirent.isDirectory()` 对**链接/junction 返回假** | 分发 preset **必须复制、不能用链接** |
| **组 id 与子行 id 同名** → 事件循环同步卡死（CPU 100%、API 全挂） | 组 id 必须 ≠ 子行 id |
| profile 行名用**子路径** → 槽位 UI 不渲染**且无报错** | 行名必须是**裸包名** |
| 插件自有 `node_modules` 里依赖 harness 子包 → peer 漂移，加载即崩 | 只依赖 `dsh-settings` + `schemastery` |
| Windows：`new URL(rel, import.meta.url).pathname` 拼出 `E:\E:\...` | 一律 `fileURLToPath`（本仓实测踩了两次） |
| Windows：相对目标 `symlinkSync` 报成功但 `lstat` ENOENT | 一律**绝对目标 + `'junction'`** |

## 3. ★ 本仓新增：产物是权威，`bundle` 是陷阱

`fairy-visual` 的客户端逻辑**有两处**：`src/client/*.js` 与 `lib/client.js`。

- `lib/client.js`（519KB / 8773 行）是**手工增强过的权威浏览器产物**，里面嵌了 compat 层
  （`settingsNamespace` 内联、HDD composer takeover、hero toggle、守卫模块等）；
- `lib/index.iife.js` 是 tsdown 的**干净产物**；
- `package.json` 的 `bundle` = `tsdown && cp lib/index.iife.js lib/client.js`
  ⇒ **跑一次 bundle，client.js 上所有手工补丁被静默覆盖**（无报错，表现为白屏/功能消失）。

**纪律**：改客户端逻辑 = 对 `lib/client.js` **和** `lib/index.iife.js` 同时做字符串级补丁
+ 把语义等价的改动同步到 `src/`。机器检查见
`fairy-visual/dsh-fairy-visual/test/guard-modules.test.js`（断言两个产物里都必须在）。

## 4. 升级时的动作清单（照做，别跳）

1. **备份** `<home>/profiles/web` 与 `<home>/settings.yaml`
2. **记基线**：当前 `capability.missing` 有哪些条目
3. `<dsh> --profile web --dump-config` → 条目还在吗、有没有报错
4. `node fairy-system/verify-build.js` 与 `node fairy-system/preflight-build.js` → **必须 PASS**
   （后者会因内核换代而报 `dsh_version`；那是**闸门该响**，按 §5 复核 pin 后再放行）
5. `node tools/run-tests.mjs` → **必须 `fail=0`**（`stale` 项要逐条对账）
6. **隔离 home 起实例**：`启动-FairyDSH焕新.vbs`（端口 3090），看日志里 5 个插件
   `"operation":"apply","outcome":"success"`，且**没有** `entries did not activate`
7. **真机五查**：浮层 / 设置页 / 新会话 / 朗读 / 余额
8. 有异常 → **先回滚 DSH 版本**，再回到本文件逐条比对（别在坏环境上继续改代码）
